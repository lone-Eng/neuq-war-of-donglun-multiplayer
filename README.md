# 东秦杀：点名册 · 可玩版

直接双击 **index.html** 即可开始游戏（纯静态、无构建、无需联网、file:// 协议可直接运行）。

想要**多人在线联机**（每个人在自己手机/电脑上玩同一局，真人不够的座位由电脑补齐）？
双击 **`start-server.bat`**，然后看[联机对战](#联机对战)那一章。

---

## 联机对战

每个人在自己的设备上玩同一局。真人不够的座位由电脑补齐，也可以让新来的人旁观。

### 怎么开（三步）

1. **房主**在这台电脑上双击 **`start-server.bat`**
   （或者命令行跑 `python server.py`；需要 Python 3.7+，本机已装 3.12）
2. 窗口里会打印几个地址，**房主自己**用浏览器打开 `http://localhost:8080/`
3. **其他人**在同一个 WiFi 下，用浏览器打开窗口里打印的另一个地址，比如 `http://10.108.126.109:8080/`
   然后点「联机对战 → 加入房间」，输入房主报给他的 **4 位房间号**

> 第一次运行 Windows 会弹防火墙提示，**必须点「允许访问」**，否则别人连不上。

### 大家不在同一个 WiFi（因特网联机）

默认方案是**房主本机开服务器**，所以只有同一个局域网够得着。要跨网玩，本质上只有一件事：
**让那个服务器在公网上够得着**。三条路，按省事程度排。

> 服务器**不跑游戏逻辑** —— 引擎在房主的浏览器里跑，它只转发消息、发静态文件。
> 所以它对机器几乎没要求，一台最便宜的云主机都富余。

#### A. 内网穿透 —— 一键版：双击 `start-online.bat` ★ 先试这个

房主**双击 `start-online.bat`** 就行。它一口气做四件事：

1. 起服务器（已经在跑就直接用，不重复起）
2. 建一条 cloudflared 隧道，把 8080 捅到公网
3. 从隧道输出里抓出 `https://xxxx-xxxx.trycloudflare.com`，并从公网这一侧回访确认真的通了
4. 用那个**公网地址**打开浏览器 —— 这一步是关键，见下面的坑

接下来照常「联机对战 → 创建房间 → 复制邀请链接」发到群里，同学点开就直接进房间。
关掉那个窗口（或 Ctrl+C）服务器和隧道一起收掉。

> **关键：房主必须用那个公网网址打开游戏，别用 `localhost`。**
> 邀请链接里的服务器地址是从**当前网页的地址**推断出来的（`net.js` 的 `serverBase()`）。
> 用 localhost 打开，发出去的链接就是 `http://localhost:8080/?room=1234` ——
> 同学点开连的是他自己的电脑。`start-online.bat` 直接帮你打开对的那个，所以别手动切回去。
>
> 万一还是用 localhost 开了房间，**大厅里会当场弹出橙色警告**告诉你链接是废的
> （`net.js` 的 `inviteWarnHtml()`，判据是 `isLoopbackUrl()`），复制链接时也会再提醒一次。

没装 cloudflared 时脚本会提示 `winget install Cloudflare.cloudflared`（装完可能要重开窗口让 PATH 生效）。
脚本在 `tools\online.ps1`，**UTF-8 带 BOM**，别把 BOM 弄丢（丢了中文会花）。

<details>
<summary>不想用一键脚本 / 不是 Windows：手动三步</summary>

以 cloudflared 为例（免注册、免安装包管理）：

```bat
:: 1) 装一次（winget 是 Windows 自带的包管理器）
winget install Cloudflare.cloudflared

:: 2) 另开一个窗口，房主照常起服务器
start-server.bat

:: 3) 再开一个窗口，把 8080 捅出去
cloudflared tunnel --url http://localhost:8080
```

第 3 步的窗口会打印一行网址，形如 `https://xxxx-xxxx.trycloudflare.com`，
**房主自己用这个网址打开游戏**（同上：别用 localhost）。

同类工具都行：`ngrok http 8080`、花生壳、frp，用法一样。
</details>

**代价**：房主电脑得一直开着；免费隧道的网址每次重启会变（反正每局都要重发链接）；
流量绕一圈隧道服务商，延迟高几十毫秒 —— 回合制游戏，基本无所谓。

#### B. 租一台公网小服务器 —— 长期玩选它

```bash
# 把整个文件夹拷上去（scp / 网盘 / git 都行），然后：
python3 server.py 8080              # 前台跑一次，先确认能起来

nohup python3 server.py 8080 > dqk.log 2>&1 &    # 想关掉终端也活着
```

然后所有人打开 `http://<公网IP>:8080/`。想上域名和 HTTPS，前面挂个 Caddy 两行就够：

```
# Caddyfile
dqk.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

> 别忘了放行端口 —— **云厂商的安全组和系统防火墙是两层，都要开**。

#### C. 云平台 / 容器 —— 不用管服务器

仓库里带了 `Dockerfile`，任何支持容器的平台（Render / Railway / Fly.io）或自己的 Docker 都能直接跑：

```bash
docker build -t dqk . && docker run -p 8080:8080 dqk
```

云平台会自动设 `PORT` 环境变量，`server.py` 认它。
（那种情况下它**不会顺延端口** —— 平台把流量打到它指定的端口，顺延等于服务起来了但谁也连不上，
所以宁可直接报错退出。）

> 免费档的两个坑：一是不活动会休眠，第一个连的人要等十几秒；
> 二是这游戏用**长轮询**，每个客户端会挂着一个 25 秒的请求不放，并发数低的档可能不够。

#### 三条路怎么选

| | 成本 | 房主电脑要开着 | 地址稳定 | 要动手吗 | 适合 |
|---|---|---|---|---|---|
| **A 内网穿透** | 免费 | 要 | 每次重启会变 | 双击 `start-online.bat` | 今晚就想玩一局 |
| **B 公网服务器** | 约 10~30 元/月 | 不用 | 稳定，可上域名 + HTTPS | 要租、要传文件 | 经常开局 |
| **C 云平台** | 有免费档 | 不用 | 平台给 | 要会点容器 | 不想碰运维 |

#### 安全提醒

`server.py` **没有任何鉴权**，房间号只有 4 位数字，猜得到。所以：

- 它是给**熟人局**用的，别当公开对战平台
- 别长期挂在公网上不关，开完那一局就停掉
- 房主浏览器里跑着完整引擎，**理论上能看到所有人的身份**（见下方「联机的已知限制」）

#### 别的情况

- **手机开热点**：房主用手机开热点，所有人的设备连这个热点。服务器启动时打印的
  `192.168.137.x` 通常就是热点网段，用那一个 —— 这是局域网方案，最省事。
- **手动填地址**：用 `file://` 打开单文件版时推断不出地址，在「联机对战」界面展开的
  服务器地址栏里手动填 `https://<隧道域名>` 或 `http://<主机>:<端口>` 即可。

### 联机时的规则细节

| 项目 | 说明 |
|---|---|
| 隐藏信息 | 手牌、牌堆顺序、未公开的身份都**只发当事人**；别人的手牌在你这边是等长的背面牌（所以"手牌 N 张"、距离、可选目标都照常算） |
| 日志 | 【查寝】【窃听】这类"观看手牌"的日志**只有当事人看得到原文**，其他人看到的是脱敏版本（规则书明确这些是私下查看） |
| 【侃山】拼绩点 | 双方牌面**全场公开** —— 规则书写的是"同时亮出、过程公开" |
| 出牌区 | 联机时房主端强制「自动清空」：手动清空会让引擎等本机点击，从而卡住全桌。客户端自己的「点击清空」照常可用（变成个人显示偏好） |
| 节奏 | 全桌共享，任何人点「节奏」按钮都会改所有人的速度 |
| 掉线 | 掉线或 60 秒不响应的人，他的回合由电脑代打，回来之后自动交还（日志里会有提示） |
| 旁观 | 进房间时选「旁观」，或者座位坐满后再进来的人，都只收公开信息，看不到任何手牌和身份 |
| 刷新页面 | 自动认领回原来的座位（房间号/身份令牌存在浏览器本地） |

### 联机的已知限制

1. **房主最好保持页面开着** —— 游戏引擎跑在房主的浏览器里。他关掉页面之后，
   别人可以点「我来接手」用存档接着打（见上文），但接手是从当前回合开头重来的，
   而且原房主那个座位会转成电脑托管。
   另外浏览器会**节流后台标签页**，房主把窗口切走会让全桌明显变慢（页面上有提示）。
2. **房主理论上能看到所有人的身份**（引擎在他浏览器内存里）。和朋友之间玩够用，
   但它不是防作弊的线上对战平台。
3. **不支持断点续玩** —— 中途服务器挂了或者房主关了页面，这局得重开。
4. 游戏里的【宿舍断网】是**牌堆重洗触发的游戏机制**，和真实网络状况无关。

## 新手指南（发给别人看）

**最省事的入门方式不是让他读文档，是让他在游戏里打一局。** 开始界面点**「新手教学局」**：

- 4 人局（最短的完整对局），你的身份**固定是学生**，目标是把院长打倒
- 起手牌固定成【上课点名】【代课】【请假条】【借笔记】四张，一张教一件事
- 电脑强制切到「简单」档，不会精准集火把你秒了；院长多给几滴血，免得两轮就结束
- 每个关键节点都会在**手牌上方弹出一张带「教学」角标的卡片**
  （出牌阶段 / 选目标 / 被人点名 / 弃牌 / 濒死…），每条只弹一次，
  点「知道了」收起，点「退出教学」随时退出

打完这一局，基础就都会了 —— 比 180KB 的规则书管用。

想先看文字版：**`东秦杀-教程.html`** —— 一个自包含的单文件教程，发给要一起玩的人。
打开就是一页图文指南：四种身份、六个阶段、牌怎么用、必须懂的八个词、上手三步、
界面怎么看、联机怎么玩、常见问题，最后附 **全部武将**和**全部卡牌**的速查表。

**它和游戏数据同源**：武将表、卡牌表、牌堆张数都是从 `js/data.js` 现场生成的，
所以永远不会写着写着就过期。改完 `data.js` 或技能文案之后重新生成一次：

```bat
powershell -ExecutionPolicy Bypass -File tools\build-guide.ps1
```

## 手机版（单文件）

**`东秦杀-mobile.html`** —— 把 HTML + 全部 CSS + 全部 JS 内联成一个文件（约 435 KB），**拷到手机上用浏览器打开即可玩**，不需要其他任何文件、不联网。
它同时也是**顺带更新 `js/sources.js` 的地方** —— 那个文件是"双击 index.html 也能导出分享版"的关键（见「复盘」一节）。

- 生成/更新：在本目录运行 `build-mobile.ps1`（每次改完源码重新跑一次即可，脚本会自动做 **16 项完整性 + 编码检查**）
- 手机版现在也内联了 `js/net.js`：用 `file://` 打开时，「联机对战」会让你手动填服务器地址，同样能加入房间
  （不过更省事的做法是直接让手机浏览器打开 `http://房主IP:8080/`）
- ⚠️ **维护须知 1**：`build-mobile.ps1` 必须保持**纯 ASCII**。PowerShell 5.1 按 ANSI/GBK 解析 .ps1，一旦在脚本里写中文字面量，输出就会变成 `鐐瑰嚮...` 这类乱码。需要中文时请从 UTF-8 源文件读取，或用 `[char]0x4E1C` 码点拼接。构建后的自检项 `cjk-*` / `patch-ascii` 会立刻发现这类问题。
- ⚠️ **维护须知 2**：要新增一个 `js/xxx.js` 让移动版也带上，需要同时改三处 ——
  `index.html` 加一行 `<script src="js/xxx.js"></script>`、`build-mobile.ps1` 第 22 行的白名单数组、
  以及第 104 行的 `<script>` 数量阈值。**文件名只能由字母组成**（内联用的正则限制），
  所以 `net-lobby.js` 这种带连字符的名字会被原样留下来、导致 `no-ext-refs` 自检失败。
- ⚠️ **维护须知 3**：`css/mobile.css` 现在**同时**被 `index.html`（`<link>`）和
  `build-mobile.ps1`（内联）引用。打包脚本里专门有一个分支吃掉那行 `<link>`，
  否则产物里会出现 `href="css/` 而让 `no-ext-refs` 失败。
- ⚠️ **产物文件名**：脚本用「目录名 + `-mobile.html`」命名。当前目录叫「东秦杀 - 联机」，
  所以它生成的是 **`东秦杀 - 联机-mobile.html`**，**不会**覆盖已有的 `东秦杀-mobile.html`。
- 传到手机：微信/QQ 发给自己 → 用浏览器打开；或存进"文件"App；iOS 可再"添加到主屏幕"当 App 用
- 同一个文件在电脑上打开也能玩：窗口宽度 ≤ 900px 自动切成手机布局，更宽则用桌面布局

### 联机是怎么实现的

理解这一点能省掉很多困惑：**服务器上不跑任何游戏逻辑**。

```
   ┌── 房主浏览器（权威）───────────┐        ┌── server.py ──────────┐
   │  完整引擎在这里跑               │◄──────►│  静态文件服务          │
   │  本地照常渲染 + 录制事件广播     │ 长轮询 │  房间 + 消息中转       │
   └───────────────────────────────┘        └───────────────────────┘
   ┌── 玩家浏览器（瘦客户端）───────┐              ▲
   │  同一套 ui.js / fx.js          │──────────────┘
   │  收快照 + 事件流 + 被询问       │
   └───────────────────────────────┘
```

客户端跑的是**完整的真实 UI 层**，所以出牌阶段、电风扇/粉笔那种"嵌套问两次再出牌"的
交互全都原样复用，一行没改 —— 客户端只是把最终答案发回房主。这也解释了上面那条
"房主必须保持页面开着"的限制。

**为什么不装 Node**：这台机器只有 Python。而引擎是 1700 行 JS，在 Python 里跑不现实；
房主浏览器本来就完整持有引擎，只要把「询问」和「表现」两条边接成网络就行。

**为什么用长轮询而不是 WebSocket**：Python 标准库没有 WebSocket，手搓 RFC6455 帧解析
风险大；长轮询是纯 HTTP，穿内网穿透/代理更稳，`curl` 就能调试。回合制卡牌对延迟不敏感。

## 三种玩法

开始界面最上面那行「玩法」切换。斗地主和 2V2 都**没有身份**，队友明置，直接开打。

| 玩法 | 人数 | 说明 |
|---|---|---|
| **身份局** | 4–8 | 经典玩法：猜身份、打对手、藏自己。一局 30–40 分钟 |
| **2V2** | 固定 4 | 1、4 号位一队（红）对 2、3 号位一队（蓝），座位交错所以左右都是敌人。开局前**互相禁选**（各禁 1 名武将），一方两人全灭即负。起手做了两头补偿：1 号位第一回合只摸 1 张、4 号位起手 5 张 |
| **斗地主** | 固定 3 | 1 个地主对 2 个农民。开局先**叫分**（不叫/1/2/3，必须高于当前最高分，叫满 3 分直接当地主）—— 叫分是盲叫，发牌前谁也没牌可看。地主 +1 体力上限、从 5 张候选里选将（农民 3 张）、起手 4 张 + 3 张底牌，另有**【飞扬】【跋扈】**两个专属技能 |

技术上是 `js/engine.js` 顶部的一张 **`FORMAT` 表**：三种玩法共用同一套规则引擎，
差异（胜负判定、先手、起手张数、阵营可见性、击杀奖惩）全部收在那张表里。
`ui.js` / `net.js` / `main.js` / `ai.js` **不准直接读 `G.format`**，只能调 `E.sideInfo` /
`E.winOf` 这些导出函数 —— 这条纪律是"三种玩法共用一套规则"不腐烂的唯一保证。

AI 那边也一样：所有决策都汇聚到 `ai.js` 的 `threat()` 一个函数上，
无身份局的改动面就是给它加一条 `sideThreat` 支路。

## 音频

| | 说明 |
|---|---|
| 音效 | Web Audio **实时合成**，不需要任何音频文件 |
| **背景音乐** | `audio/bgm/bgm.mp3`（已装一首 FreePD 的公版曲目，CC0 无需署名）。**只在牌局外放** —— 开始界面 / 大厅 / 选角 / 结算循环，进了对局就暂停（牌局里音效很密会互相盖）。**单文件手机版没有 BGM**：它没有那个目录，代码静默跳过。为什么不做内联见 [audio/bgm/README.md](audio/bgm/README.md) |
| **语音报牌** | 出牌时念出牌名。两条路：**音色包**（`audio/voice/`，见下）优先；没有就退回浏览器自带的 `speechSynthesis`（零文件、离线可用，音色取决于你系统装了哪些中文语音包）。设置里能开关、选音色、试听 |
| **技能语音** | **每个技能一句贴合角色气质的台词**（37 名角色 × 2 个技能 = 74 句，在 `js/data.js` 的 `SKILL_LINES`），主动技、触发技、锁定技**都算**。同一个技能 4 秒内不重复念（否则【正义】【过滤】这种每次挨打都触发的会念成一片）。技能台词刚念过时会把报牌名让位 1.5 秒，免得把台词打断 |

### 音色包（12 种开源音色，可切）

`audio/voice/` 里是**预生成好的 mp3**：45 张牌名 + 74 句技能台词 = 119 句 × 12 种音色
= 1428 个文件，共约 8.6 MB（32kbps 单声道，一句约 6 KB）。
配音用的是开源模型 **[Kokoro-82M-v1.1-zh](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)**
（Apache-2.0，82M 参数，`make-voice.ps1` 在本机 CPU 上离线生成，中文说话人由龙猫数据无偿提供给该模型）。
比系统语音像人得多，而且**换电脑也是同一个声音** —— 系统语音的音色是跟着操作系统走的。

生成/换音色：双击 **`make-voice.bat`**（第一次会建 `tools\.voicevenv`、装依赖、下模型，约 1GB）。
模型仓库里有 **100 个中文说话人**（55 女 `zf_*` + 45 男 `zm_*`）：

```bat
make-voice.bat -Audition        :: 100 个音色各念一句，生成 tools\_audition\index.html 给你挑
:: 挑好后把 id 填进 tools\voicegen.py 顶部的 VOICES，再跑一次 make-voice.bat
```

台词表是**从 `js/data.js` 现场解析**的，不维护第二份清单 —— 加了新武将新牌，重跑一次就有对应语音。
中途 Ctrl+C 也不怕：已生成的会跳过，再跑接着做。

- 设置里那一行「音色」：`系统女声 / 系统男声 / 女声 1-6 / 男声 1-6`，点「试听」当场比
- **双击 index.html（file://）也能选**：清单做成可被 `<script>` 加载的 `packs.js`
  —— 浏览器不让 file:// 页面 `fetch` 本地文件，用 fetch 的话音色列表会只剩系统那两个
- **没生成过音色包也能玩**：静默退回系统语音（某个句子缺配音时也是）
- **单文件手机版没有音色包**：它没有 `audio/` 目录，和 BGM 同样的取舍
- 音频文件不进源码快照（`tools/backup.ps1` 特意排除），换机器重新生成即可

发音时机在 `engine.js` 的 `log()` 里统一嗅探 —— 全项目每个技能生效时都会留一条带技能名的日志，
所以一个钩子就够，不用在 70 多个技能实现里各插一行。[自测](tools/js_test.js)里有一条**覆盖率**断言
钉着"每个技能都得有台词"，漏了新角色不会有报错，只会永远不吭声。

换 BGM：跑 `powershell -ExecutionPolicy Bypass -File tools\get-bgm.ps1`（它从 FreePD
拉候选曲目并校验确实是音频），或者直接把别的文件改名成 `audio/bgm/bgm.mp3` 覆盖掉。
换配音音色：跑 `make-voice.bat`（见上面的[音色包](#音色包12-种开源音色可切)）。

## 电脑强度（简单 / 普通 / 困难）

开始界面和联机大厅都能选，默认**普通**。三档**只调参数，不换决策逻辑**：

| 旋钮 | 简单 | 普通 | 困难 |
|---|---|---|---|
| 评分随机项（越大越常做次优选择） | 46 | 10 | 3 |
| 身份推断权重 | 0.35 | 1.00 | 1.70 |
| 出牌阶段"低级失误"概率 | 30% | 7% | 0% |
| 响应窗口"漏时机"概率 | 22% | 5% | 0% |

- **简单**：几乎不做身份推断，打谁基本看牌面 + 大量随机；常常"想不出该干嘛"就直接过，也经常忘了打代课
- **困难**：精算身份、**优先集火同一目标**、技能用在刀刃上、不漏任何响应窗口

两条刻意的边界：**「不打已知队友」不随难度变化**（那是基本能力不是难度，否则简单档就成了"坏掉"）；
**简单档的低级失误不作用于濒死自救**（跳过自救等于送死）。

联机时由**房主**设定 —— 电脑跑在房主那边。

## 打完一局的评分与 MVP

一局结束时，除了"谁赢了"，还会算一份**每个人这局干了什么**的账：

| 项目 | 分值 |
|---|---|
| 阵营胜利 | +30 |
| 造成伤害 | 每点 +3 |
| 击杀 | 每个 +15 |
| 救援濒死 | 每次 +12（救谁都算） |
| 治疗他人 | 每点 +4（治自己不算） |
| 发动技能 | 每次 +2（**上限 20**） |
| 存活到终局 | +8 |

**总分最高的是 MVP**，结算界面金框高亮。**全场公开**——所有人的伤害/击杀/救援/治疗/技能次数都列出来，谁划水一目了然。并列时依次比 击杀 → 伤害 → 座位号。

> 评分刻意**不给身份加成**：身份输赢已经由那 30 分体现了，再加一次就是重复计分。
> 所以**打得凶但输掉的人，分数完全可以压过躺赢的队友**——这个榜看的是"你做了什么"，不是"你抽到了什么"。

浏览器还会记住**本机战绩**（共几局 / 胜几场 / MVP 次数 / 单局最高分），显示在结算界面底部，只存在本机不上传。

## 复盘

**打完一局可以存下来重看。** 结束界面有两个按钮：

| 点这个 | 得到 | 对方怎么放 |
| --- | --- | --- |
| 保存复盘 | 一个 `.json` | 开始界面点「看复盘」把它选出来 |
| **导出分享版** | 一个 `.html`（约 430 KB） | **点开就放** —— 游戏本体已经打包在里面了 |

发到群里用「导出分享版」：一个文件，点开就是能暂停、能 1×/2×/4× 变速的回放，
对方不用装游戏、不用「另存 → 用『看复盘』打开」。

放出来之后 —— 出牌区、音效、飘字、查考勤翻牌全部照常重演。

**三种打开方式都能导出**，包括双击 `index.html`（`file://`）：

| 你在哪玩的 | 源码从哪来 |
| --- | --- |
| 服务器地址（`start-server.bat`） | 直接 `fetch` 真实的 `js/` `css/` 文件 |
| 手机单文件版 | 源码本来就内联在页面里 |
| **双击 `index.html`** | 网页不许读自己的文件，改读 `js/sources.js` —— 一份由 `build-mobile.ps1` 顺带生成的源码包 |

> `js/sources.js` 是**生成**的。改完 `js/` 或 `css/` 里的东西，跑一次
> `build-mobile.ps1`（或单独的 `tools\build-sources.ps1`）把它刷新一遍 ——
> 否则双击打开时导出的复盘里会是改动**之前**的代码，而且这个错**不会报任何错**。
> 测试套件里有一条专门卡这个（`run_tests.ps1 -Export` 会拿重新生成的包和现有的比对）。

录的是**你自己那一端看到的东西**，所以：文件小；而且**复盘里天然不含别人的手牌** ——
把录像发到群里也不会泄漏任何隐藏信息。

这游戏的核心是信息不对称，"他什么时候就开始演了"只有复盘看得清。

## 房主掉线了怎么办

引擎跑在房主浏览器里，以前他一关页面这局就没了。现在：

房主每 4 秒把整局状态存一份到中转服务器。他掉线后，**其他人屏幕上会弹出一条提示**，
点「我来接手」就能用那份存档接着打下去 —— 身份、手牌、装备、血量、通知栏全都保留。

> **说清楚代价**：接手是从**当前回合的开头**继续的，不是精确到出牌阶段中间
> （引擎是 async 长链，没法序列化到一半）。所以当前行动的人这一回合会重来一次，
> 会多摸两张牌。这是失真的，但比"整局没了"好得多。

## 操作与界面

### 点棋盘选目标（不再是弹窗里找名字）

出牌阶段点一张需要目标的牌，**合法的目标会在棋盘上直接描绿边**，点人即选。

- 点已选中的人 = 取消；单目标下点另一个人 = 直接换人
- 底部操作条显示「使用【上课点名】 已选 1/1」，选够之后点「出手」
- 目标太多、面板太小（8 人局手机上）时可以点操作条上的 **「列表选择」** 退回弹窗
- 主动技、点名接力等**所有**目标选择都走同一套手感

**出手前会要一次确认**（身份局点错人代价很大）。嫌慢的话在弹窗里关掉：
「规则 → 出手前确认」—— 关掉后选完目标立即结算。

### 键盘

| 按键 | 作用 |
|---|---|
| `Enter` | 确认（选目标时出手 / 关掉确认类弹窗） |
| `Esc` | 取消（退选目标 / 关掉**可取消**的弹窗） |
| `1`–`9` | 按座位号选目标 |
| `空格` / 点击 | 出牌区「点击清空」模式下继续 |

> Esc 只能关掉有取消路径的弹窗。「是否打出代课」这类必须表态的询问不会响应 Esc ——
> 关掉它会让引擎永远等下去。

### 座位布局：队列 / 座位圈

顶栏 **「布局」** 按钮切换：

- **横向队列**（手机默认）：所有座位横排，可横滑
- **座位圈**（宽屏默认）：以**你自己为基准**围成一圈，你在正下方，出牌顺序顺时针推进。
  这样"相邻"就是真的挨着，**距离**一眼能看出来 —— 横排时隔着一个人和隔着三个人看起来差不多

### 等别人时的反馈

- 轮到某人时，他的面板上有金色**「▶ 当前回合」**缎带 + 呼吸光晕
- 正在等他做决定时显示 **「思考中 23s」** 读秒（联机时全场都看得到），
  超时会被电脑接管 —— 不用再猜对方是在想还是掉线了
- **手牌超过上限会提前警告**：「手牌 6 / 上限 3　出牌阶段结束时需弃 3 张」——
  这是在**出牌阶段**就提示的，你还有机会多打两张牌避免弃牌

### 手牌与牌面

- 手牌按 **基本牌 → 装备 → 事件 → 延时** 分组排列，同名牌相邻，组内点数大的在前
- 每张牌左下角有**类型角标**（基本/装备/事件/延时），一眼分类
- 完整说明仍然在**长按**（或右键）里 —— 牌面上不再印"长按看详情"占位文字

### 弃牌堆能翻开看

顶栏的「弃牌 N」是**可以点的** —— 点开能看到弃牌堆里都有什么牌、各多少张、什么点数花色，
按出现次数排序。弃牌堆本来就是公开信息（每次弃牌都写进了日志），能翻它，老手才能数牌。

### 色盲友好

判定（查考勤）的成败完全建立在"这张牌是红还是黑"上，光靠颜色对红绿色盲玩家不友好。
现在红黑有**三重冗余编码**：

1. 颜色（原样保留）
2. 花色字形（♥♦ / ♠♣）
3. **纹理** —— 红牌左边缘是斜纹、黑牌是点阵；查考勤那张还会把「红 / 黑」直接写出来

### 新手引导

第一次进游戏会自动弹一个四步引导（看手牌 → 选目标 → 看状态 → 别慌），
之后不再打扰。想再看：「规则 → 新手引导」。

### 快捷语（联机）

顶栏 💬 按钮，8 句预设 + 自由输入（30 字），**全场可见**。
说的话会在该角色面板上冒个气泡，同时进战斗日志。单机时按钮自动隐藏。

### 旁观席

旁观时底部变成一条观战信息条（当前回合 / 第几轮 / 存活人数），不显示手牌区。

## 角色唯一性

- **你可以多选一**：候选数由"你的选角候选"决定（3 / 5 / 2 / 8 张），只要求给每位电脑至少留 1 张武将，不再按人数硬性压缩；
- 你选定后，**没选走的那几张候选回归武将池**，电脑再从剩下的武将里按强度评分挑选；
- 电脑之间也互不重复，另有一层兜底校验，若仍检测到重复会立即替换并在日志告警；
- 选角界面会显示"你从 N 名武将中选 1 名；其余 X 名电脑会从剩下的 M 名里挑选"；
- 自检包含"当前对局角色不重复"断言。

## 修复记录

| 问题 | 原因 | 修复 |
|---|---|---|
| **点击装备牌提示"没有合法目标"、装备不上** | 装备牌在数据层只有 `type:'equip'`、缺 `kind` 字段，而 UI 与引擎都用 `meta.kind === 'equip'` 判断，永不成立 → UI 走到目标选择（合法目标为空）、引擎 `useCard` 也匹配不到装备分支会把牌直接丢进弃牌堆 | 数据层为全部装备牌统一补 `kind:'equip'`；自检新增"25 张装备牌均可正常装备""所有牌名都有 kind 字段"两条断言防回归 |
| 【试卷】无视防具判定在目标身上 | 判断写成了检查目标的武器 | 改为按**使用者**判定，并贯通到伤害结算（医保卡封顶、雨衣火焰 +1 一并失效） |
| 【校园卡】判定失败后无法用手牌代课 | 判定失败即关闭响应窗口 | 判定失败后重新询问同一角色（不再提供校园卡选项） |
| 【电风扇】【粉笔】绕过点名类牌次数上限 | 转化结算未校验 `usedAttackCardThisPhase` | 转化入口与结算处均加上限校验 |
| 同一局出现重复角色 | "每人 N 选 1"未限制总量，人多时角色池被抽干，后续座位回退到同一角色 | 候选数自动收敛为 `总角色数 ÷ 人数`；AI 只从未被选走的角色中挑；外加兜底替换与日志告警 |
| 面板/日志出现 `undefined` | 玩家对象缺 `name` 属性（名字在 `char.name`） | 以 getter 形式提供 `p.name` |
| 手机版注入脚本中文乱码 | PowerShell 5.1 **以 ANSI/GBK 解析 .ps1**，脚本内的中文字面量被压坏后写进 HTML | 打包脚本改为**纯 ASCII**（中文一律从 UTF-8 源文件读取，脚本内需要中文时用 `[char]0xXXXX` 码点拼接）；输出改用 .NET `WriteAllText` 写 **UTF-8 无 BOM**；新增 5 项编码自检（品牌/职务/牌名中文串抽查、补丁块纯 ASCII、无 BOM、无 `src=/href=` 外链） |

## 规则自检（验证装备是否生效）

游戏内点顶栏 **规则 → 运行自检**（或控制台执行 `runSelfTest()`），会自动校验 **30 项**并弹出报告：

- 牌堆构成：160 / 基本 85 / 事件 50（非延时 42 + 延时 8）/ 装备 25、点名册 2 张、坐骑 7 张
- 11 把武器的栏位与攻击距离、4 件防具、+1 / −1 坐骑标注
- 距离计算：基础距离、+1 坐骑、−1 坐骑、虎爷【震慑】、鸟爷【观鸟】、数学郭【极限】覆盖修正
- 防具免疫：学生证（黑色点名）/ 雨衣（点名、群伤、火焰 +1）/ 试卷无视防具 / 对照组
- 点名册解除点名次数上限、且不解除公开处刑限制、且仍受【吹牛】禁用
- 攻击范围取武器值、手牌上限 = 体力、波比【体能】+1
- 角色库：每人 ≤2 技能、无阵营字段、性别表覆盖

自检会临时构造测试角色并**跑完自动还原**，不影响正在进行的一局。

## 可选规则开关（设置栏）

这些以前堆在开始界面上，现在都收进了「设置」（见上面的「设置栏」一节）：

- **AI 接管其他玩家**：关闭后进入**热座模式**，每个座位都由玩家操作（左上角会显示"「X」的决策"）。

  界面内 **规则** 按钮可随时查看速查表。

## 已知简化（不影响正常对局）

1. **改判**：基础牌堆与基础角色没有改判来源，引擎未接入改判窗口（扩展时可在 `judgePhase` 的抽签牌翻开处插入）。
2. **断网标记**：作为可选规则（牌堆重洗时触发）保留在引擎中，默认关闭。
3. **AI 决策**：启发式评分 + 行为记忆（谁打过院长、谁救过人），不做完整贝叶斯身份推断；困难难度所需的 MCTS 见规则书 13.3。
4. **UI 交互**：目标选择使用弹窗而非拖拽；"可发动的触发技"会自动弹窗询问，不会遗漏。
5. **4 人局补偿**：学生额外 +1 张起手牌（规则书 9.5）。

## 快速验证清单

开局后按顺序检查这几项即可确认引擎正常：
1. 院长身份公开、体力比角色牌多 1、先行动、起手 5 张；
2. 出牌阶段点手牌 → 弹窗选目标 → 对方弹"是否打出代课"；
3. 点名命中后体力条减少，日志出现"受到 X 点普通伤害"；
4. 体力归零时弹出自救询问，救回后继续；
5. 有人死亡时翻开身份牌并结算奖惩（杀学生摸 3 张）；
6. 院长死亡立即结算胜负并显示身份揭示墙。

## 联机的快速验证清单

开一局联机（房主窗口 + 另一个浏览器窗口，或手机），按顺序核对：

1. 第二个窗口加入房间后，房主那边**立刻**出现这个人的名字和座位号；
2. 双方都能看到对方的角色、体力、装备、通知栏，**但看不到对方的手牌**（长按对方角色，显示的是"手牌 N"而不是牌面）；
3. 自己出牌 → 对方弹出响应窗口（代课 / 辅导员签字）；
4. 中央出牌区、飘字、音效、查考勤翻牌在**两端都有**（且只出现一次，不重不残）；
5. 有人掉线或关掉标签页 → 房主日志出现"已由电脑托管"，游戏**不卡住**，能继续打完；
6. 客户端中途**刷新页面** → 自动回到原座位，并重新弹出当时正在问他的那个询问；
7. 再开一个窗口选「旁观」→ 全程看不到任何手牌和身份，底部显示"你正在旁观本局"；
8. 手机浏览器打开 `http://主机地址:8080/` → 自动切到手机布局（不是桌面布局）。

## 开发者自测

改动引擎或联机层之后，建议跑一遍自动化测试（**都不需要装 Node**）。

**前提**：把 `server.py` 跑起来。测试全部用 Edge/Chrome 的**无头模式**真跑游戏代码，
所以需要装过 Edge 或 Chrome（Windows 自带 Edge）。

```bat
:: 默认：JS 自测（编解码 / 状态投影 / 事件回放 / 引擎回归）
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1

:: 全都跑一遍（约 1~2 分钟）
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -All

:: 单独某一套
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -Js -Net   :: 加上主机↔客户端网络往返
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -Page      :: 真实 index.html 冒烟
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -E2E       :: 两个真浏览器打一局联机
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -Mobile    :: 打包出来的单文件手机版
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -Export    :: 复盘导出（两种版本各跑一遍）

:: 中转层协议测试（纯 Python，不需要浏览器）
python -I tools\protocol_test.py
```

六个套件分别在测什么：

| 套件 | 入口 | 覆盖 |
|---|---|---|
| **JS 自测** | `tools/js_test.js` | 编解码往返（含"回传的牌必须能通过引擎的 `p.hand.includes()` 同一性校验"这条**关键**断言）、状态投影的隐藏信息规则、日志脱敏、事件录制的**重入抑制**、多真人选角、身份模式 A/B/C、点棋盘选目标、键盘、旁观席、快捷语、弃牌堆、新手引导、**新手教学局**（含"引擎真发的询问，教学认不认得出来"—— 提示是靠正则认引擎写的提示语的，改个词就会静默失效）、**存档序列化往返**（房主接手靠它）、复盘录制与分享版导出，以及**在无头环境里从头跑完一整局**（引擎改动的强回归保险） |
| **页面冒烟** | `tools/page_smoke.html` | 在**真实的 index.html** 上点完整流程：开始界面 → 联机大厅 → 返回 → 单机开局 → 选角 → 进游戏 → 再来一局 → **新手教学局**（含提示条是不是真的占到版面 —— 只查 class 是查不出"样式表少一条规则、玩家什么都看不见"的），全程断言无 JS 错误 |
| **联机端到端** | `tools/e2e_online.html` | **两个真实浏览器页面 + 真实服务器**：建房 → 加入 → 开始 → 各自选角 → 进桌面 → 快捷语气泡 → 邀请链接。核心断言是**玩家端看不到别人的手牌和身份**（手牌全是等长背面占位牌、身份除院长外全为 null、牌堆只发张数） |
| **复盘导出** | `tools/export_probe.html`、`tools/file_export_probe.html` | 三条路各验一遍：①默认（http，源码靠 `fetch`）②把**手机单文件版**放进 iframe 让它自己导出（源码是内联的，另一条分支）③**从 `file://` 打开**的页面导出（源码只能靠 `js/sources.js`，`file://` 探针故意不加 `--allow-file-access-from-files`，并且会在 `fetch` 没被挡住时自己报失败，免得变成假绿）。前两条真正作数的是 —— 把导出的 `.html` 落盘、再用无头浏览器**打开它**，看座位 / 手牌 / 复盘条有没有渲染出来：纯字符串断言分不出"导出成功"和"打开是白屏"，而白屏正是这东西坏过两次的方式。另外还有一条**源码包新鲜度**检查（重新生成一遍和现有的比 SHA256）—— 包过期不会报任何错，只会让导出的复盘装着旧代码 |
| **中转协议** | `tools/protocol_test.py` | 房间、长轮询唤醒、游标语义、消息路由、掉线重连、并发下的静态服务 |

### 为什么测试要走"结果回传"而不是 `--dump-dom`

`tools/result_sink.py` 是个只在本机跑的小服务，浏览器跑完自测把结果 POST 给它、
它写进文件。用它是被逼的：自测里有**长轮询**，一个 `fetch` 会长时间挂起，
而 Chromium 的虚拟时钟遇到挂起的网络请求会暂停，于是 `--virtual-time-budget`
永远不触发、`--dump-dom` 永远不返回 —— 测试会看起来"卡死"。
