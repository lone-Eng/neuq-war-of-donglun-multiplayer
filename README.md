# 东秦杀：点名册 · 可玩版

直接双击 **index.html** 即可开始游戏（纯静态、无构建、无需联网、file:// 协议可直接运行）。

想要**多人在线联机**（每个人在自己手机/电脑上玩同一局，真人不够的座位由电脑补齐）？
双击 **`start-server.bat`**，然后看[联机对战](#联机对战)那一章。

---

## 联机对战

每个人在自己的设备上玩同一局。真人不够的座位由电脑补齐，也可以让新来的人旁观。

### 怎么开（三步）

1. **房主**在这台电脑上双击 **`start-server.bat`**
   （或者命令行跑 `python server.py`；需要 Python 3.7+，本机已装 3.12）
2. 窗口里会打印几个地址，**房主自己**用浏览器打开 `http://localhost:8080/`
3. **其他人**在同一个 WiFi 下，用浏览器打开窗口里打印的另一个地址，比如 `http://10.108.126.109:8080/`
   然后点「联机对战 → 加入房间」，输入房主报给他的 **4 位房间号**

> 第一次运行 Windows 会弹防火墙提示，**必须点「允许访问」**，否则别人连不上。

### 大家不在同一个 WiFi 怎么办

- **手机开热点**：房主用手机开热点，电脑连上，其他人的设备也连这个热点。
  服务器启动时打印的 `192.168.137.x` 那个地址通常就是热点网段，用那一个。
- **公网穿透**：如果大家天各一方，需要把 8080 端口穿透到公网（frp / ngrok / 花生壳 等）。
  穿透成功后，让所有人**用穿透出来的公网地址**打开游戏就行 —— 服务器地址是从网页地址
  自动推断的，不需要额外配置。
- **手动填地址**：如果是用 `file://` 直接打开的单文件版，或者地址推断不对，在
  「联机对战」界面展开的服务器地址栏里手动填 `http://主机:端口`。

### 联机时的规则细节

| 项目 | 说明 |
|---|---|
| 隐藏信息 | 手牌、牌堆顺序、未公开的身份都**只发当事人**；别人的手牌在你这边是等长的背面牌（所以"手牌 N 张"、距离、可选目标都照常算） |
| 日志 | 【查寝】【窃听】这类"观看手牌"的日志**只有当事人看得到原文**，其他人看到的是脱敏版本（规则书明确这些是私下查看） |
| 【侃山】拼绩点 | 双方牌面**全场公开** —— 规则书写的是"同时亮出、过程公开" |
| 出牌区 | 联机时房主端强制「自动清空」：手动清空会让引擎等本机点击，从而卡住全桌。客户端自己的「点击清空」照常可用（变成个人显示偏好） |
| 节奏 | 全桌共享，任何人点「节奏」按钮都会改所有人的速度 |
| 掉线 | 掉线或 60 秒不响应的人，他的回合由电脑代打，回来之后自动交还（日志里会有提示） |
| 旁观 | 进房间时选「旁观」，或者座位坐满后再进来的人，都只收公开信息，看不到任何手牌和身份 |
| 刷新页面 | 自动认领回原来的座位（房间号/身份令牌存在浏览器本地） |

### 联机的已知限制

1. **房主最好保持页面开着** —— 游戏引擎跑在房主的浏览器里。他关掉页面之后，
   别人可以点「我来接手」用存档接着打（见上文），但接手是从当前回合开头重来的，
   而且原房主那个座位会转成电脑托管。
   另外浏览器会**节流后台标签页**，房主把窗口切走会让全桌明显变慢（页面上有提示）。
2. **房主理论上能看到所有人的身份**（引擎在他浏览器内存里）。和朋友之间玩够用，
   但它不是防作弊的线上对战平台。
3. **不支持断点续玩** —— 中途服务器挂了或者房主关了页面，这局得重开。
4. 游戏里的【宿舍断网】是**牌堆重洗触发的游戏机制**，和真实网络状况无关。


## 手机版（单文件）

**`东秦杀-mobile.html`** —— 把 HTML + 全部 CSS + 全部 JS 内联成一个文件（约 253 KB），**拷到手机上用浏览器打开即可玩**，不需要其他任何文件、不联网。

- 生成/更新：在本目录运行 `build-mobile.ps1`（每次改完源码重新跑一次即可，脚本会自动做 **16 项完整性 + 编码检查**）
- 手机版现在也内联了 `js/net.js`：用 `file://` 打开时，「联机对战」会让你手动填服务器地址，同样能加入房间
  （不过更省事的做法是直接让手机浏览器打开 `http://房主IP:8080/`）
- ⚠️ **维护须知 1**：`build-mobile.ps1` 必须保持**纯 ASCII**。PowerShell 5.1 按 ANSI/GBK 解析 .ps1，一旦在脚本里写中文字面量，输出就会变成 `鐐瑰嚮...` 这类乱码。需要中文时请从 UTF-8 源文件读取，或用 `[char]0x4E1C` 码点拼接。构建后的自检项 `cjk-*` / `patch-ascii` 会立刻发现这类问题。
- ⚠️ **维护须知 2**：要新增一个 `js/xxx.js` 让移动版也带上，需要同时改三处 ——
  `index.html` 加一行 `<script src="js/xxx.js"></script>`、`build-mobile.ps1` 第 22 行的白名单数组、
  以及第 104 行的 `<script>` 数量阈值。**文件名只能由字母组成**（内联用的正则限制），
  所以 `net-lobby.js` 这种带连字符的名字会被原样留下来、导致 `no-ext-refs` 自检失败。
- ⚠️ **维护须知 3**：`css/mobile.css` 现在**同时**被 `index.html`（`<link>`）和
  `build-mobile.ps1`（内联）引用。打包脚本里专门有一个分支吃掉那行 `<link>`，
  否则产物里会出现 `href="css/` 而让 `no-ext-refs` 失败。
- ⚠️ **产物文件名**：脚本用「目录名 + `-mobile.html`」命名。当前目录叫「东秦杀 - 联机」，
  所以它生成的是 **`东秦杀 - 联机-mobile.html`**，**不会**覆盖已有的 `东秦杀-mobile.html`。
- 传到手机：微信/QQ 发给自己 → 用浏览器打开；或存进"文件"App；iOS 可再"添加到主屏幕"当 App 用
- 同一个文件在电脑上打开也能玩：窗口宽度 ≤ 900px 自动切成手机布局，更宽则用桌面布局

### 联机是怎么实现的

理解这一点能省掉很多困惑：**服务器上不跑任何游戏逻辑**。

```
   ┌── 房主浏览器（权威）───────────┐        ┌── server.py ──────────┐
   │  完整引擎在这里跑               │◄──────►│  静态文件服务          │
   │  本地照常渲染 + 录制事件广播     │ 长轮询 │  房间 + 消息中转       │
   └───────────────────────────────┘        └───────────────────────┘
   ┌── 玩家浏览器（瘦客户端）───────┐              ▲
   │  同一套 ui.js / fx.js          │──────────────┘
   │  收快照 + 事件流 + 被询问       │
   └───────────────────────────────┘
```

客户端跑的是**完整的真实 UI 层**，所以出牌阶段、电风扇/粉笔那种"嵌套问两次再出牌"的
交互全都原样复用，一行没改 —— 客户端只是把最终答案发回房主。这也解释了上面那条
"房主必须保持页面开着"的限制。

**为什么不装 Node**：这台机器只有 Python。而引擎是 1700 行 JS，在 Python 里跑不现实；
房主浏览器本来就完整持有引擎，只要把「询问」和「表现」两条边接成网络就行。

**为什么用长轮询而不是 WebSocket**：Python 标准库没有 WebSocket，手搓 RFC6455 帧解析
风险大；长轮询是纯 HTTP，穿内网穿透/代理更稳，`curl` 就能调试。回合制卡牌对延迟不敏感。

## 复盘

**打完一局可以存下来重看。** 结束时点「保存这局复盘」，得到一个 `.json`；
开始界面点「看复盘」选它就放出来 —— 出牌区、音效、飘字、查考勤翻牌全部照常重演，
可以暂停、1×/2×/4× 变速。

录的是**你自己那一端看到的东西**，所以：文件小；而且**复盘里天然不含别人的手牌** ——
把录像发到群里也不会泄漏任何隐藏信息。

这游戏的核心是信息不对称，"他什么时候就开始演了"只有复盘看得清。

## 房主掉线了怎么办

引擎跑在房主浏览器里，以前他一关页面这局就没了。现在：

房主每 4 秒把整局状态存一份到中转服务器。他掉线后，**其他人屏幕上会弹出一条提示**，
点「我来接手」就能用那份存档接着打下去 —— 身份、手牌、装备、血量、通知栏全都保留。

> **说清楚代价**：接手是从**当前回合的开头**继续的，不是精确到出牌阶段中间
> （引擎是 async 长链，没法序列化到一半）。所以当前行动的人这一回合会重来一次，
> 会多摸两张牌。这是失真的，但比"整局没了"好得多。

## 操作与界面

### 点棋盘选目标（不再是弹窗里找名字）

出牌阶段点一张需要目标的牌，**合法的目标会在棋盘上直接描绿边**，点人即选。

- 点已选中的人 = 取消；单目标下点另一个人 = 直接换人
- 底部操作条显示「使用【上课点名】 已选 1/1」，选够之后点「出手」
- 目标太多、面板太小（8 人局手机上）时可以点操作条上的 **「列表选择」** 退回弹窗
- 主动技、点名接力等**所有**目标选择都走同一套手感

**出手前会要一次确认**（身份局点错人代价很大）。嫌慢的话在弹窗里关掉：
「规则 → 出手前确认」—— 关掉后选完目标立即结算。

### 键盘

| 按键 | 作用 |
|---|---|
| `Enter` | 确认（选目标时出手 / 关掉确认类弹窗） |
| `Esc` | 取消（退选目标 / 关掉**可取消**的弹窗） |
| `1`–`9` | 按座位号选目标 |
| `空格` / 点击 | 出牌区「点击清空」模式下继续 |

> Esc 只能关掉有取消路径的弹窗。「是否打出代课」这类必须表态的询问不会响应 Esc ——
> 关掉它会让引擎永远等下去。

### 座位布局：队列 / 座位圈

顶栏 **「布局」** 按钮切换：

- **横向队列**（手机默认）：所有座位横排，可横滑
- **座位圈**（宽屏默认）：以**你自己为基准**围成一圈，你在正下方，出牌顺序顺时针推进。
  这样"相邻"就是真的挨着，**距离**一眼能看出来 —— 横排时隔着一个人和隔着三个人看起来差不多

### 等别人时的反馈

- 轮到某人时，他的面板上有金色**「▶ 当前回合」**缎带 + 呼吸光晕
- 正在等他做决定时显示 **「思考中 23s」** 读秒（联机时全场都看得到），
  超时会被电脑接管 —— 不用再猜对方是在想还是掉线了
- **手牌超过上限会提前警告**：「手牌 6 / 上限 3　出牌阶段结束时需弃 3 张」——
  这是在**出牌阶段**就提示的，你还有机会多打两张牌避免弃牌

### 手牌与牌面

- 手牌按 **基本牌 → 装备 → 事件 → 延时** 分组排列，同名牌相邻，组内点数大的在前
- 每张牌左下角有**类型角标**（基本/装备/事件/延时），一眼分类
- 完整说明仍然在**长按**（或右键）里 —— 牌面上不再印"长按看详情"占位文字

### 弃牌堆能翻开看

顶栏的「弃牌 N」是**可以点的** —— 点开能看到弃牌堆里都有什么牌、各多少张、什么点数花色，
按出现次数排序。弃牌堆本来就是公开信息（每次弃牌都写进了日志），能翻它，老手才能数牌。

### 色盲友好

判定（查考勤）的成败完全建立在"这张牌是红还是黑"上，光靠颜色对红绿色盲玩家不友好。
现在红黑有**三重冗余编码**：

1. 颜色（原样保留）
2. 花色字形（♥♦ / ♠♣）
3. **纹理** —— 红牌左边缘是斜纹、黑牌是点阵；查考勤那张还会把「红 / 黑」直接写出来

### 新手引导

第一次进游戏会自动弹一个四步引导（看手牌 → 选目标 → 看状态 → 别慌），
之后不再打扰。想再看：「规则 → 新手引导」。

### 快捷语（联机）

顶栏 💬 按钮，8 句预设 + 自由输入（30 字），**全场可见**。
说的话会在该角色面板上冒个气泡，同时进战斗日志。单机时按钮自动隐藏。

### 旁观席

旁观时底部变成一条观战信息条（当前回合 / 第几轮 / 存活人数），不显示手牌区。

| **横向座位队列** | 所有角色（**包括你自己**）按座位顺序从左到右排成一行，自动换行、自动等宽；你自己的面板用金色边框与顶边标出 |

## 角色唯一性

- **你可以多选一**：候选数由"你的选角候选"决定（3 / 5 / 2 / 8 张），只要求给每位电脑至少留 1 张武将，不再按人数硬性压缩；
- 你选定后，**没选走的那几张候选回归武将池**，电脑再从剩下的武将里按强度评分挑选；
- 电脑之间也互不重复，另有一层兜底校验，若仍检测到重复会立即替换并在日志告警；
- 选角界面会显示"你从 N 名武将中选 1 名；其余 X 名电脑会从剩下的 M 名里挑选"；
- 自检包含"当前对局角色不重复"断言。

## 修复记录

| 问题 | 原因 | 修复 |
|---|---|---|
| **点击装备牌提示"没有合法目标"、装备不上** | 装备牌在数据层只有 `type:'equip'`、缺 `kind` 字段，而 UI 与引擎都用 `meta.kind === 'equip'` 判断，永不成立 → UI 走到目标选择（合法目标为空）、引擎 `useCard` 也匹配不到装备分支会把牌直接丢进弃牌堆 | 数据层为全部装备牌统一补 `kind:'equip'`；自检新增"25 张装备牌均可正常装备""所有牌名都有 kind 字段"两条断言防回归 |
| 【试卷】无视防具判定在目标身上 | 判断写成了检查目标的武器 | 改为按**使用者**判定，并贯通到伤害结算（医保卡封顶、雨衣火焰 +1 一并失效） |
| 【校园卡】判定失败后无法用手牌代课 | 判定失败即关闭响应窗口 | 判定失败后重新询问同一角色（不再提供校园卡选项） |
| 【电风扇】【粉笔】绕过点名类牌次数上限 | 转化结算未校验 `usedAttackCardThisPhase` | 转化入口与结算处均加上限校验 |
| 同一局出现重复角色 | "每人 N 选 1"未限制总量，人多时角色池被抽干，后续座位回退到同一角色 | 候选数自动收敛为 `总角色数 ÷ 人数`；AI 只从未被选走的角色中挑；外加兜底替换与日志告警 |
| 面板/日志出现 `undefined` | 玩家对象缺 `name` 属性（名字在 `char.name`） | 以 getter 形式提供 `p.name` |
| 手机版注入脚本中文乱码 | PowerShell 5.1 **以 ANSI/GBK 解析 .ps1**，脚本内的中文字面量被压坏后写进 HTML | 打包脚本改为**纯 ASCII**（中文一律从 UTF-8 源文件读取，脚本内需要中文时用 `[char]0xXXXX` 码点拼接）；输出改用 .NET `WriteAllText` 写 **UTF-8 无 BOM**；新增 5 项编码自检（品牌/职务/牌名中文串抽查、补丁块纯 ASCII、无 BOM、无 `src=/href=` 外链） |

## 节奏（默认放慢，强调"看得清"）

顶栏 **`节奏：标准`** 按钮可在 标准(1.35×) → 很慢(1.9×) → 快(0.6×) → 极速(0.15×) 之间切换，**所有停顿与动画同比例缩放**。

| 摸牌 | 0.4 秒 | 面板飘出 **+2 张** |

## 规则自检（验证装备是否生效）

游戏内点顶栏 **规则 → 运行自检**（或控制台执行 `runSelfTest()`），会自动校验 **30 项**并弹出报告：

- 牌堆构成：160 / 基本 85 / 事件 50（非延时 42 + 延时 8）/ 装备 25、点名册 2 张、坐骑 7 张
- 11 把武器的栏位与攻击距离、4 件防具、+1 / −1 坐骑标注
- 距离计算：基础距离、+1 坐骑、−1 坐骑、虎爷【震慑】、鸟爷【观鸟】、数学郭【极限】覆盖修正
- 防具免疫：学生证（黑色点名）/ 雨衣（点名、群伤、火焰 +1）/ 试卷无视防具 / 对照组
- 点名册解除点名次数上限、且不解除公开处刑限制、且仍受【吹牛】禁用
- 攻击范围取武器值、手牌上限 = 体力、波比【体能】+1
- 角色库：20 名、每人 ≤2 技能、无阵营字段、性别表覆盖

自检会临时构造测试角色并**跑完自动还原**，不影响正在进行的一局。

## 可选规则开关（开始界面）

- **保护轮**：第一圈内任何角色体力不会降到 1 以下（新手推荐）。
- **AI 接管其他玩家**：关闭后进入**热座模式**，每个座位都由玩家操作（左上角会显示"「X」的决策"）。
- 界面内 **规则** 按钮可随时查看速查表；**动画** 按钮可切换 正常/快速/极速/慢速。

## 已知简化（不影响正常对局）

1. **改判**：基础牌堆与基础角色没有改判来源，引擎未接入改判窗口（扩展时可在 `judgePhase` 的抽签牌翻开处插入）。
2. **断网标记**：作为可选规则（牌堆重洗时触发）保留在引擎中，默认关闭。
3. **AI 决策**：启发式评分 + 行为记忆（谁打过院长、谁救过人），不做完整贝叶斯身份推断；困难难度所需的 MCTS 见规则书 13.3。
4. **UI 交互**：目标选择使用弹窗而非拖拽；"可发动的触发技"会自动弹窗询问，不会遗漏。
5. **4 人局补偿**：学生额外 +1 张起手牌（规则书 9.5）。

## 快速验证清单

开局后按顺序检查这几项即可确认引擎正常：
1. 院长身份公开、体力比角色牌多 1、先行动、起手 5 张；
2. 出牌阶段点手牌 → 弹窗选目标 → 对方弹"是否打出代课"；
3. 点名命中后体力条减少，日志出现"受到 X 点普通伤害"；
4. 体力归零时弹出自救询问，救回后继续；
5. 有人死亡时翻开身份牌并结算奖惩（杀学生摸 3 张）；
6. 院长死亡立即结算胜负并显示身份揭示墙。

## 联机的快速验证清单

开一局联机（房主窗口 + 另一个浏览器窗口，或手机），按顺序核对：

1. 第二个窗口加入房间后，房主那边**立刻**出现这个人的名字和座位号；
2. 双方都能看到对方的角色、体力、装备、通知栏，**但看不到对方的手牌**（长按对方角色，显示的是"手牌 N"而不是牌面）；
3. 自己出牌 → 对方弹出响应窗口（代课 / 辅导员签字）；
4. 中央出牌区、飘字、音效、查考勤翻牌在**两端都有**（且只出现一次，不重不残）；
5. 有人掉线或关掉标签页 → 房主日志出现"已由电脑托管"，游戏**不卡住**，能继续打完；
6. 客户端中途**刷新页面** → 自动回到原座位，并重新弹出当时正在问他的那个询问；
7. 再开一个窗口选「旁观」→ 全程看不到任何手牌和身份，底部显示"你正在旁观本局"；
8. 手机浏览器打开 `http://主机地址:8080/` → 自动切到手机布局（不是桌面布局）。

## 开发者自测

改动引擎或联机层之后，建议跑一遍自动化测试（**都不需要装 Node**）。

**前提**：把 `server.py` 跑起来。测试全部用 Edge/Chrome 的**无头模式**真跑游戏代码，
所以需要装过 Edge 或 Chrome（Windows 自带 Edge）。

```bat

powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1

:: 全都跑一遍（约 1~2 分钟）
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -All

:: 单独某一套
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -Js -Net   :: 加上主机↔客户端网络往返
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -Page      :: 真实 index.html 冒烟
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -E2E       :: 两个真浏览器打一局联机
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1 -Mobile    :: 打包出来的单文件手机版

:: 中转层协议测试（纯 Python，不需要浏览器）
python -I tools\protocol_test.py
```

四套测试分别在测什么：

| 套件 | 入口 | 覆盖 |
|---|---|---|
| **JS 自测** | `tools/js_test.js` | 编解码往返（含"回传的牌必须能通过引擎的 `p.hand.includes()` 同一性校验"这条**关键**断言）、状态投影的隐藏信息规则、日志脱敏、事件录制的**重入抑制**、多真人选角、身份模式 A/B/C、点棋盘选目标、键盘、旁观席、快捷语、弃牌堆、新手引导、**存档序列化往返**（房主接手靠它）、复盘录制，以及**在无头环境里从头跑完一整局**（引擎改动的强回归保险） |
| **页面冒烟** | `tools/page_smoke.html` | 在**真实的 index.html** 上点完整单机流程：开始界面 → 联机大厅 → 返回 → 单机开局 → 选角 → 进游戏，全程断言无 JS 错误 |
| **联机端到端** | `tools/e2e_online.html` | **两个真实浏览器页面 + 真实服务器**：建房 → 加入 → 开始 → 各自选角 → 进桌面 → 快捷语气泡 → 邀请链接。核心断言是**玩家端看不到别人的手牌和身份**（手牌全是等长背面占位牌、身份除院长外全为 null、牌堆只发张数） |
| **中转协议** | `tools/protocol_test.py` | 房间、长轮询唤醒、游标语义、消息路由、掉线重连、并发下的静态服务 |

### 为什么测试要走"结果回传"而不是 `--dump-dom`

`tools/result_sink.py` 是个只在本机跑的小服务，浏览器跑完自测把结果 POST 给它、
它写进文件。用它是被逼的：自测里有**长轮询**，一个 `fetch` 会长时间挂起，
而 Chromium 的虚拟时钟遇到挂起的网络请求会暂停，于是 `--virtual-time-budget`
永远不触发、`--dump-dom` 永远不返回 —— 测试会看起来"卡死"。
